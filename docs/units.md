# Object types

Generated by `scripts/re/gen_units.py` from the game data - do not edit. Every unit and building type with its id,
its **identifier** and its English name. The identifier is the type's internal name in the game data, the same in
every game language: lowercase, every run of other characters one `_` (`b  Guard Tower - Bronze` ->
`b_guard_tower_bronze`). The prefixes are the designers': `b` building, `a` aircraft, `inf`/`arch`/`cav` + the
epoch infantry, archers, cavalry, `gun` siege and guns, `x` special variants, `amb` animals, `res` resources.

Kind is the game's family of the type (its armour and bonus class) - in the texts `kind.<kind>`: `me.count(kind.towers)`
counts every tower whatever its epoch, `unit.<identifier>` only that type (config/personalities/README.md). The mod reads
the types, their names and families from the data the game has loaded, so a data mod's types count too; this list
is the retail game's (some of its types the game doesn't load: the `x ... ME` variants, a few mines and trees).
The AI code names the types it needs by identifier as well (dll/game/unit_ids.h: `UT(B_FARM)`), looked up when the game
starts - a type a data mod hasn't got is logged and left out. What a type is to the AI (a tower, a wall, a gate,
siege, a ram, a citizen, a transport, a fishing boat) it takes from the family and the game's class of the type, so
a data mod's new tower or transport counts without a name; the game log lists them (`# units: towers: ...`). Towers,
walls and gates it builds from their named lines: the game would let it build the Missile Base and castle walls
too (the pipe's `canbuild P`). Buildings come first in each epoch.
